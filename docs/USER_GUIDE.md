# 使用与故障排查

## 入口与服务

双击项目根目录的 `声笺.lnk` 或 `start-app.cmd`。图标由 `create-shortcut.cmd` 生成；`create-shortcut.cmd -Desktop` 可额外创建桌面入口。移动文件夹后请重新生成。

关闭窗口不会停止服务，再次打开复用 `127.0.0.1:3210`。需要停止时运行 `powershell -ExecutionPolicy Bypass -File .\stop-app.ps1`。

更新后端时，先等待转写结束、保存文稿，再运行 `powershell -ExecutionPolicy Bypass -File .\restart-service.ps1`。重启脚本验证进程身份并保留页面会话令牌，但不会保留服务内存中的任务。旧页面中的 Key 和文字仍在浏览器里；刷新才加载新版界面代码，刷新前先保存。

## 时间戳听检

建议先用 1 分钟间隔测试短录音。每段独立请求 API，时间范围来自实际切段记录；播放器定位可能有几十毫秒编码偏差。检查总时长、结尾时间、段数及失败、未处理、空结果；听检中间、边界和结尾。

100% 处理覆盖只能说明各音频片段都收到响应，不能证明没有漏字。空结果可能是静音，也可能漏识别。旧纯文本没有可信分段对应，需要重新转写才能生成时间戳。编辑文字不改变原任务统计；采用聊天回复后隐藏该统计，恢复原文可重新查看。

## 导出文件位置

新版点击导出后由服务直接写入项目 `download/`，页面显示完整路径。文件沿用录音名称，重名编号，不覆盖。导出的是当前编辑器内容；Word 支持段落与一至三级标题，其他 Markdown 标记可能按文字保留。

如果仍看到“已生成下载文件”而没有路径，说明窗口运行旧界面代码。新后端仍会保存旧请求，通常命名为 `转写文稿.md` / `.docx`，浏览器也可能额外尝试下载一份。先查看该目录并保存内容，再重新打开页面，无需重新调用转写 API。

## 故障排查

| 表现 | 原因与处理 |
|---|---|
| EACCES / EPERM | 服务运行环境拒绝外网访问。从 Windows 图标或 CMD 正常启动，必要时运行重启脚本。改存 Key 到 TXT 无法修复网络权限。 |
| ENOTFOUND / EAI_AGAIN | DNS 失败，检查网络与 DNS。 |
| ECONNRESET / 超时 | 检查网络与代理。应用不自动重复付费请求。 |
| 401 | 检查 Key 是否有效，以及与服务商是否匹配。 |
| 403 / 429 | 检查权限、额度、地区及限流。 |
| 404 | 核对准确的模型名称与服务商。 |
| 无法读取音轨 | 检查文件完整性、音轨与 FFmpeg 安装。 |

带本地会话令牌的 `/api/network?provider=siliconflow` 不发送用户 Key；`connected:true` 且 HTTP 401 只说明官方接口可达，不说明用户 Key 有效。开发时已复现受限 Node 进程的 EACCES，并在正常权限下重启后确认网络连通。

## 数据范围

Key 仅留在当前页面内存或用户自行配置的服务环境变量，不写入 URL、浏览器存储或仓库。浏览器只保存模型名称、选择与自定义列表。临时音频在任务结束后清理；异常终止可能留下 `.runtime/audio-*`，可在停止服务后手工清理。

`download/` 中的文稿保留在磁盘，不随关闭窗口删除。应用没有自动草稿、版本历史或云端备份。
